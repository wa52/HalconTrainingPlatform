# 目标检测数据、标注与训练（rectangle1）

原生 WPF 入口为 **数据集 → 目标检测 · 主动学习**。不改变分类、语义分割训练链。

## 当前训练规则

- 全部未移除图像参与，不以已确认、待审核、草稿或需重标状态筛选。
- 有人工标注或草稿时，使用该层当前框；包括人工清空的空框草稿，不恢复旧预测。否则使用已有预测框，保留当前每图预测框数量限制。
- 没框就是负样本，直接保存空框参加训练，无需负样本标签、专用按钮或自动补框。需要预测时仍可主动使用原有预测操作。
- 无法读取的原图或无效框明确报错，不以“全部训练”为由忽略错误或偷偷剔除图像。
- 至少 5 张图像并有目标框。只有无框图片无法单独训练检测模型，应与有框图片合并。
- 训练/HDICT 导出前保存当前图像尚未提交的编辑为草稿；不自动标成人工已确认。其他图像的未保存编辑仍应在切图前保存。

确认与“全部确认”继续记录人工复核结果；独立的“导出已确认 COCO”仍为已复核标注归档。训练、合并 HDICT 导出采用全量快照，两者用途不同。

## 文件夹和类别

导入含类别子目录的根目录，子目录内更深层的批次目录仍归属该文件夹。根目录散放图片缺少归属，会跳过并提示。类别名称来自目录，但目录名不生成检测框。

左侧只浏览当前类别图像；可以拖动画框、移动和缩放已有框，保存草稿或确认。中间大图与缩略图总览共用数据源，当前框为空的条目显示“负样本”。顶部汇总全量图像与负样本数。

本类训练保留独立模型，预测只处理当前类别。合并训练包含所有文件夹的未移除图像；纯背景文件夹贡献负样本，不额外创建没有目标框的检测类别。保留已有目标类别 ID 和名称，模型兼容性仍由原生参数验证。

多个有框类别各自至少 5 张图片时，可在“更多操作”选择分类别并行训练，最多同时 1 或 2 个任务。每个任务保存独立快照、Worker、日志和模型；一个失败不影响其他任务，停止取消运行与排队任务。纯背景类别通过合并训练使用。

## 从数据集移除图像

选中一张图片后点击图像列表标题旁的图片减号图标，与“删除框”分开，只有一个入口。确认窗口展示完整路径和影响，默认取消。移除后选择相邻图像；最后一张移除后清空选择、框和画布。

仅修改当前会话，不删除磁盘原图，不更改其他类别、已有模型或历史导出。列表、缩略图、数量和训练资格同步刷新；新预测、导出和训练不包含该图。移除记录在重启、重新扫描、追加原图和合并预测后仍有效。

会话原子保存，写入失败保留旧数据。操作前备份在 `active-learning/sessions/backups`，不混入自动加载列表；当前没有恢复按钮，可从备份恢复会话。通过浏览页打开的源 `.hdict` 仍只读。

## HDICT 导出和合并训练

顶部导出生成全量 COCO 快照，再通过原生 `write_dict/read_dict` 写入二进制 `.hdict` 并逐项复读，核对每张图片、框、尺寸、类别与划分。空框图片也保留样本字典和空的 `bbox_*` 元组。COCO 的 `halcon_bbox` 保存原始行列坐标，避免 xywh 往返误差。

每次输出到 `active-learning/exports/<时间_唯一编号>/`，包括 `.hdict`、`images/` 副本、`annotations.json`、`provenance.json`、原生导出报告。`image_dir=images`，移动时需保留整个目录。来源会话和原图不改写，历史导出不覆盖。

HALCON 按实际目标类别分层，空框图片分为背景组，种子 42，默认训练/验证/测试 70%/15%/15%。极少样本可能有空集合，报告实际数量；图像级划分不能证明相似工件无泄漏。优化器只读 train，不能将“全部图像入选”误解为验证和测试也更新权重。

合并训练使用可见的尺寸、Batch、Epoch 和学习率，输出 `models/detection/<根数据集名>/run_.../` 的一个多类别模型，独立模型输出到对应类别目录。保存模型、配套预处理、参数、类别、日志、数据来源和逐轮性能。支持兼容权重继续微调与每轮检查点，见 [训练性能说明](TRAINING_PERFORMANCE.md)。

`provenance.json` 记录全量选择策略、图片/框数、负样本数、原复核状态及人工/预测/负样本标签来源。未确认预测参与训练不代表标注已经人工验收，训练 Loss 也不是 mAP。

## 预测和审核

已有模型预测支持 YOLO `.pt` 和 HALCON `.hdl`；HALCON 需要同目录匹配的 `preprocess.hdict`。阈值默认 0.05，按类别保存；每图最多预测框为 1～300，文件夹模式默认 1，人工标注不被此限制截断。预测失败保留原数据；无检测明确显示零框，不虚构框。

“全部确认”只确认当前类别有有效框的待审核图片，不确认坏框、缺图、需重标或其他类别。操作前备份，取消不更改标注。该操作不再是训练准入条件。

## 环境与验证

HALCON 24.11、.NET 8、Windows x64；图像通过 `HSmartWindowControlWPF` 显示，训练和预测通过独立 Worker，停止/关闭释放进程。主训练与主动学习 GPU 作业互斥。并发共享显存，不保证提速。

YOLO 使用 `HALCON_TRAINING_PYTHON` 指定的独立 Python 环境及 `tools/yolo_active_learning.py`。权重和原图不随源码提交。首次运行需要已配置的 PyTorch/Ultralytics 环境和可用权重。

数据层：`dotnet run --project tests/HalconTraining.ActiveLearning.Smoke/HalconTraining.ActiveLearning.Smoke.csproj -c Release`。覆盖标签优先级、空草稿负样本、未确认全量入选、背景类别、导出、移除/恢复/失败、隔离、调度和取消。

YOLO 转换：项目虚拟环境运行 `python -m unittest discover -s tests -p test_yolo_active_learning.py`，验证空标签负样本文件和类别映射。

原生全量验证：`--validate-all-image-training --validation-output <目录>`，要求 `HALCON_TRAINING_HOME=<目录>/workspace`，仅创建隔离检查图片，实际导出 HDICT 并复读；追加 `--manual-all-image-check` 留下真实编辑窗口供审查，Alt+F4 退出。本轮实测 7 张图像，4 个未确认人工框、3 张空框负样本、1 个目标类别全部保留。

本轮已通过数据层、6 项 Python 转换测试、原生 WPF 和 HDICT 写入复读；没有重新执行 GPU 优化器训练、完整 mAP 或多 DPI 验收。既往真实训练/推理记录不能代替本轮精度结论。
