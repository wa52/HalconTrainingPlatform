# HALCON 训练平台 UI 设计 v1

界面稿：`UI_DESIGN.html`。面向使用 HALCON 24.11 的视觉工程师，默认从已标注的 HALCON `.hdict` 数据集进入训练流程。页面中的扬声器为 SVG 示意图，统计、曲线与实验均为样例，不代表实际训练结果。正式桌面程序仍采用 WPF，不依赖浏览器；HTML 用于先评审布局和交互。

## 视觉规范

- 浅灰蓝工作台 `#EDF1F5`，白色面板 `#FFFFFF`，文字 `#203247`，分隔线 `#DCE3EB`。
- 蓝色操作与选中态 `#2464A2`；完成/真值辅助色 `#218577`；待处理/缺陷标注 `#D08335`；失败 `#BF555A`。状态同时显示文字，避免只靠颜色辨识。
- 图像区域 `#171F28`，与外层控件区明确区分。主张使用深色图像显示框，不让白色背景干扰缺陷观察。
- 中文采用 Microsoft YaHei UI，数字、文件名、坐标采用 Cascadia Code / Consolas。标题 23px，正文 13px，数据说明 10–11px；正式 WPF 使用 DIP 并检查 DPI 缩放。
- 左导航 190px、右属性栏 280px，主区弹性布局，间距 8 / 16 / 24px。优先覆盖 1360×820 及以上桌面；较窄宽度折叠导航文字和右栏。

## 四个页面

| 项目总览 | 定位当前数据与实验 | 数据版本、最近实验、运行环境、下一步流程与环境检查结果。 |

## 固定模型库与训练归档

模型统一放在程序数据目录下的 `models/`，默认根目录由正式程序通过 Windows 用户数据目录定位，避免写入安装目录。每个任务类别使用固定文件夹：`detection`、`semantic_segmentation`、`instance_segmentation`、`classification`、`multilabel_classification`、`anomaly_detection`、`gc_anomaly_detection`、`ocr_detection`、`ocr_recognition`。水平框与旋转框同属目标检测，在模型元信息中区分。

“类别”在此按训练任务类别理解；同一模型中的多个缺陷标签共同保存在模型和 `classes.json` 中。每次训练生成独立目录 `models/<任务类别>/<数据集名称>/<时间戳_运行ID>/`，保留历史模型，禁止静默覆盖。训练页归档路径只读，由任务识别和数据集名称自动生成，用户无需每次指定输出目录。

训练完成后保存模型、预处理字典、类别映射、参数、日志和元信息，自动登记到模型管理。模型加载验证单独显示状态，未通过验证的模型仍可在模型管理中查看，但不能宣称已可交付。失败/取消的运行保留日志与中间产物，明确标记，不展示为训练完成。正式持久化由 Application 编排、Persistence 管理目录与索引、Worker 写出 HALCON 模型；临时目录写入完整后再发布，并校验路径及文件完整性。

当前 HTML 仅展示归档目录与分类文件夹方案，尚未执行模型文件写入。

## 直接选择 HALCON 数据集

1. 点击“浏览数据集”，通过系统文件选择器选中现有 `.hdict/.json`。不设导入向导、复制方式、版本创建或冻结步骤。`.dltp` 仍需先在 DLT 导出数据集。
2. 正式程序直接读取所选文件，展示任务、样本数量、类别 ID 与自动划分结果；解析失败时显示文件及错误原因，保持训练不可用。
3. 数据集页与训练页共用同一文件选择。训练前检查缺图、标注及路径，不通过检查则定位具体问题；修正文件后重新读取。

任务类型自动识别，数据集页显示只读结果，训练页同步展示对应参数，不要求手工选择语义分割或目标检测。正式识别以 HALCON 读取后的标注结构与元信息为依据，不根据扩展名或文件名猜测：分割标注、完整的水平/旋转框字段、实例区域及分类标签分别进入对应 schema 校验。检查整个样本集合；空标注样本不作为任务冲突依据。信息不足、任务字段冲突或模型任务不匹配时显示具体问题，并在必要时提供确认入口，不静默选择某种任务。异常数据不能单独区分 AD/GC-AD，OCR 数据也可能存在组件歧义，需结合模型或明确的任务元信息。

界面稿只展示自动识别的结果位置和待解析状态；默认目标检测是示例，选择本地文件后立即清空示例任务及专属参数。真实任务识别由正式程序中的 HALCON Worker 实现。

训练环境问题放在总览与训练前检查，数据浏览不被训练验证阻塞。正式训练记录数据集路径、文件摘要及参数，保证可追溯，不要求用户先建立数据版本。

## 最新界面调整

移除顶部项目名称与副标题；移除独立的标注复核和评估对比页面及全部跳转入口。数据集页保留只读标注预览；标注问题由外部工具修正后重新读取。训练页保留训练/验证曲线，模型管理承担加载验证与交付。此调整目前作用于 UI 设计稿，正式 WPF 程序将在设计确认后同步。

### 训练页简化与参考项目

按用户最新要求移除独立实验配置页，与训练监控合并为一个训练页。参考 speaker-inspection/u训练/trainer_app/ui/main_window.py 的数据集、划分、训练参数、增强分组与右侧监控/日志布局。采用 HALCON .hdict 数据与 .hdl 模型，不复制 YOLO 的 .pt/ONNX、workers 或 Mosaic 等专属选项。参数可编辑，保存按钮更新本次界面会话摘要；尚未调用真实训练和持久化。


### 任务名称跟随数据集

任务名称直接使用数据集文件名，去掉末尾 `.hdict` 或 `.json` 扩展名，保留中文、空格和名称中的其它点号。训练页任务名称只读，重新浏览数据集时立即同步更新；不要求用户另起任务名称。例：`扬声器缺陷.hdict` → 任务“扬声器缺陷” → `models/detection/扬声器缺陷/<时间戳_运行ID>/`。重复训练使用版本子目录，不在显示名称中强加后缀。正式持久化处理 Windows 保留名称、路径字符和同名数据集冲突，来源信息与运行ID写入元信息；显示名称始终保留原数据集名称。

### HALCON 自带模型

训练页基础模型自动匹配，不要求手工选择或浏览。根据已识别的数据集任务应用 assets/pretrained/catalog.json 的任务默认映射，读取项目内模型副本。目标检测与实例分割需要从骨干构建对应模型；多标签和 OCR 需配置或加载对应组件。更换数据集时清空旧模型，识别不明确时不猜测。7 个默认模型已复制到项目 assets/pretrained 并逐文件校验 SHA-256；源安装目录不作修改。模型副本不提交 Git，catalog.json 保存文件名、大小、哈希、任务映射和待验证状态。界面稿已展示自动匹配字段；正式 Worker 的任务识别、模型加载与构建尚待接入。

## 选择数据集后自动划分

正式流程：选中文件 → HALCON 读取与任务识别 → 校验样本与类别 → 自动生成训练/验证/测试划分 → 匹配基础模型 → 等待开始训练。默认比例 70% / 15% / 15%，不要求用户单独点击划分；高级设置允许改比例或使用已有划分。选新文件时清除上一份划分，比例设置沿用当前会话。

优先按工件/批次分组，并在可行时保持类别分布；无分组元信息时按固定随机种子划分，并说明缺少防泄漏分组依据。组划分导致比例近似时展示实际数量与比例；样本过少、无法生成非空集合或关键类别无法覆盖时明确提示，不静默报告完成。默认只生成运行使用的划分副本，保持源数据集不被改写；每次训练记录种子、策略、样本分配与来源摘要。

HTML 默认设置与折叠摘要已改为自动划分，比例变化同步更新摘要；选择真实文件仍显示“解析后自动划分”。真实划分需要 Worker 解析出的样本，界面稿没有执行实际划分。

## 已接入真实字典预览（2026-10-13）

HTML 通过仅绑定 127.0.0.1:8770 的 tools/dataset-preview-server.cjs 调用短生命周期 Worker 的 --dataset-inspect。浏览器选中的字典临时存入项目 artifacts，Worker 使用 HALCON read_dict 解析，完成后删除临时副本。原文件不改写。服务校验来源、文件扩展名与字典大小上限，原图仅通过随机令牌访问。

当前能力：读取样本与类别，识别语义分割/水平框/旋转框/实例分割/分类等标注结构，显示前100张真实图像、搜索与划分筛选、只读样本详情、自动匹配基础模型；默认以固定种子42做70/15/15预览划分，显式工件/批次ID优先分组。无分组元信息时显示提示。此预览划分尚未持久化为正式训练输入，当前训练参数页的比例/种子编辑尚未传给该预览接口。

验证数据：用户桌面 NH320标签.hdict，332张、2类、332份分割标注，默认划分232/50/50；原图可读。另验证桌面的目标检测（90张）与实例分割（230张）可识别。损坏字典返回HALCON读字典错误，页面显示读取失败，随后重新选择正常文件可恢复。Worker Release构建0警告0错误。

限制：未做像素标注叠加、掩膜尺寸/ID全面验证、正式训练。JSON以HALCON tuple数组方式读取，不支持的嵌套形状会报错。浏览器不提供完整原文件路径，绝对image_dir可解析；相对路径目前以临时副本目录为基准，缺图会报告，后续需补原图根目录重定位。OCR/异常任务有组件歧义时保持待模型确认。界面原有按钮中未接入的功能仍属设计演示。

## 本次真实语义分割训练

已增加 SemanticTrainer 与 --semantic-train CLI，使用HALCON附带的create_dl_preprocess_param_from_model/preprocess_dl_samples进行预处理，并调用train_dl_model_batch。输入为用户桌面NH320标签.hdict；Compact语义分割基础模型使用项目副本，不覆盖基础权重或源数据。当前配置512×512、Batch2、60轮、学习率0.001、常量像素权重1、关闭增强。划分随机种子42，训练232/验证50/测试50，保存完整索引split.json。

每轮保存model.hdl，保存preprocess.hdict、training_params.json与真实JSON行日志。完成后manifest.json标记trained_pending_validation；独立--semantic-evaluate进程负责重载与验证/测试mIoU，保存validation_report.json。页面轮询真实日志展示进度和Loss，不生成假指标。当前训练入口由CLI执行；HTML“开始/停止”尚未连接作业提交/取消。当前实现只覆盖语义分割，不代表其它任务训练均已接通。源数据缺少明确工件/批次ID，本次按图像随机划分，评估需注意相似样本泄漏的可能性。

## 原图模型测试（2026-10-13）

模型管理 → 测试模型 → 选择原图，可多选最多20张。无需导入测试字典或提供标注。SemanticTester在独立Worker进程加载已训练模型及其preprocess.hdict，自动预处理原图并执行真实ApplyDlModel；full_domain预测掩膜用nearest_neighbor还原到原图尺寸。界面并排显示原图和可调透明度的预测叠加，显示耗时、预测面积及保存目录。

原图副本、类别ID掩膜和结构化结果自动保存到results/tests/<数据集名>/<唯一ID>/；“保存叠加图”将当前透明度的overlay.png写入该目录。每张图片独立进程、独立输出，损坏图片失败后继续下一张。服务仅监听127.0.0.1，模型与结果路径由服务登记令牌选择，不接受浏览器任意输出路径。

实际验证：两张NH320原图均成功，尺寸221×252；损坏PNG与正常原图同批，失败1张、成功1张；透明度0与100可调；overlay.png成功保存且与原图/掩膜同尺寸。第一次GPU预热推理约57.8秒，随后约178–183毫秒（不含模型加载与预处理），不是稳定吞吐基准。当前接通语义分割，未提供真值时不显示准确率；WPF界面尚未同步此测试入口。

本地界面服务：node tools/ui-preview-server.cjs（8768）；解析/测试服务：node tools/dataset-preview-server.cjs（8770）。运行前需完成Worker Release构建并配置HALCONROOT、许可证及GPU环境。截图UI_MODEL_TEST_PREVIEW.png包含实际原图测试结果，不应随公开源码提交。

原图测试显示调整：默认叠加透明度60%，前景使用青色并绘制类别边界；两侧预览等比例适应窗口且完整显示原图。重新验证两张原图均成功，可切换查看，预测前景占比分别10.24%与10.11%，叠加图保存成功。
