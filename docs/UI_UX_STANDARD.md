# 通用软件 UI/UX 设计与审美规范

## 1. 核心目标

所有软件界面必须兼顾美观（专业、协调、现代）、清晰（信息结构明确）、高效（减少寻找、理解和操作成本）、一致（统一视觉与交互）和易用（符合习惯并提供反馈）。功能质量、视觉质量和交互质量同时达标，不能仅以功能完成、控件正常显示或编译通过作为完成标准。

## 2. 设计优先于编码

重要界面创建或修改前，先确定目标用户与场景、核心任务与主要操作，再规划信息层级、功能分区和操作流程；选择适合产品的视觉风格，建立颜色、字体、间距和组件规则，审查冗余与不协调后再开发。不能简单排列默认组件，也不能仅靠颜色、阴影、圆角或边距代替布局设计。

## 3. 视觉审美原则

- **视觉层次**：每页有明确焦点，通过字体、大小、粗细、颜色、位置和留白表达重要性。主要内容突出，避免所有组件权重相同，或多个高对比度按钮、卡片和色块争夺注意力。
- **比例与空间**：区域宽高、密度和比例协调；避免一侧拥挤、另一侧无意义空白。留白服务分组和节奏，优先自适应布局，适应窗口、屏幕比例和缩放。
- **字体与排版**：统一标题、正文、说明、状态和数值层级，控制字体与字号数量。同类信息使用一致行高和间距；保证对比度，正确处理长文本、路径、数值和表格的换行、截断和滚动，避免过密、过小或分散。
- **颜色**：按产品、环境与用户选择主题，不强制所有软件同色。统一背景、表面、主色、文字、边框和状态色；控制高饱和强调色，保持成功、警告、错误、信息语义一致，不堆叠无意义装饰。
- **一致性**：同类功能使用一致组件与交互；按钮、输入、下拉、标签页、弹窗、提示统一尺寸、边框、圆角、间距及状态。优先设计令牌和可复用组件，不允许页面风格割裂。

## 4. 交互设计原则

每页有核心任务，主要操作容易发现，功能按实际流程组织，删除重复入口与无价值步骤。图标语义明确，必要时采用图标加文字，纯图标提供清晰提示；支持悬停的平台默认延迟约 1.5 秒。点击、选中、加载、完成、失败和禁用都有明确反馈。危险或不可逆操作提供必要确认。保持键盘、触摸及辅助技术可访问性，不能牺牲可理解性追求极简。

## 5. 状态驱动的界面设计

至少考虑初次使用、无数据、正常工作、加载/执行、成功、错误/异常、大数据量和长内容。空状态不能保留巨大无意义空白；执行时有明确反馈，用户能够判断下一步操作。

## 6. 组件设计要求

优先复用成熟、可靠、适合技术栈的组件与设计系统。基础组件统一样式并具备完整状态；尺寸适合鼠标、键盘或触摸操作，避免过小按钮、模糊输入与图标。不能为减少组件隐藏必要功能，也不能为展示功能无限堆叠卡片、按钮、表格和参数。组件服务信息与操作。

## 7. 视觉参考与设计判断

重要 UI 设计先研究同类成熟商业软件，分析布局、层次、导航、排版、空间和交互，提取原则并按具体用途适配，保持自身风格。不能机械复制管理后台、仪表盘、暗色科技风或其他模板，也不能用“流行”“极简”“工业风”“现代化”等形容词代替设计方案。选择必须说明实际用途与理由。

## 8. 必须进行视觉审查

UI 修改后构建并启动真实软件，获取当前运行截图，检查整体比例、空间、信息层次、焦点、操作入口、排版、颜色、对齐、间距和组件一致性；检查遮挡、重叠、裁切、溢出和异常留白；检查不同尺寸、比例与缩放，覆盖空、正常、运行、错误状态，验证主要操作、反馈和既有功能。发现问题后修改并复查。不能用设计稿或生成图代替；无法运行时列出未验证项，不得声称视觉验收通过。

## 9. 审美自评与改进

每次视觉审查按 1–5 分评估七个维度：整体协调性（比例、平衡、统一）、视觉层次（重点）、排版质量（可读性）、组件品质（细节和状态）、空间利用（密度和比例）、交互体验（清晰、自然、易发现）、产品完成度（整体品质）。分数仅诊断，不能代替真实截图、交互和用户反馈。低于 4 分要记录具体问题与修复措施；严重布局错误、不可读内容、遮挡、关键入口隐藏、视觉不一致必须继续修改。

## 10. 自动视觉迭代闭环

需求分析 → 视觉规划 → UI 实现 → 真实运行 → 截图审查 → 问题定位 → UI 改进 → 功能回归 → 再次审查。

每次审查指出具体问题，先修布局与层次，再修微观细节；保持业务功能完整，保存重要修改前后证据。未达标继续迭代，环境或权限受限时报告阻碍与未完成项。无真实验证证据不能宣布达到商业软件品质。

## 11. 最终交付标准

功能符合需求、信息结构清晰、主操作易发现、布局协调且层次明确、排版与组件统一、无严重遮挡裁切、主要状态合理、有真实运行和交互检查、原功能无回归、有实际截图或可信证据，方可完成 UI 任务。不仅可用，还应专业、顺畅且具备成熟产品的完成度。
